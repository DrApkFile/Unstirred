## The two attempts before this one

- **The first attempt failed at `cargo fmt --all -- --check`.** Four files, all of them this step's
  own: a re-export whose doc comment moved it out of sort order, and three import lists one
  character over the width. `cargo fmt --all` fixed them.
- **The second attempt failed at the test step, on A37**, with
  `Unreachable { url: ".../rooms/holders-room/admit", detail: "client error (SendRequest)" }`.
  Nothing in this step touches that path. The gate refuses an over-long `Content-Length` *without
  reading the body* — which is what A37 exists to show — so it answers and closes while the client
  is still writing its 256 KiB, and under load the client can be reset before it reads the answer.
  The same target alone passes (`cargo test --release -p unstirred-gate --all-features --test http`:
  7 passed, 97.01s, against 139.03s for the same target in the failing run). It is recorded as a
  finding in `briefing/BUILD_NOTES.md` — the gate's behaviour is the intended one and the
  observation is what is racy — and nothing was changed for it. The run above is the re-run.
